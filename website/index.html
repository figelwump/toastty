Webhooks

Lumen sends an HTTPS POST to your endpoint whenever something happens in your store.

Payload

Each event sends event, timestamp, and a flat payload map.Each event includes id, type, created_at, and a nested data object.

{ "event": "order.paid",
  "timestamp": 1727712000,
  "payload": { ... } }{ "id": "evt_91f",
  "type": "order.paid",
  "created_at": "2026-09-30T16:00:00Z",
  "data": { ... } }

Retries

Failed deliveries retry with exponential backoff for up to 24 hours.

Building blocks

Everything on screen is something your agent can use.

Toastty is a terminal multiplexer at its core, so it works with Claude Code, Codex, Cursor, Grok Build, OpenCode, Pi, or any CLI you run. What it adds is a set of pieces your agents can arrange for you.

PR #128
1 2 2 3 4
5toastty action run workspace.create · panel.create.local-document · workspace.set-annotation
  1. Workspaces and subspacesOne per project or task, in the sidebar. A subspace nests new work under the session that started it.
  2. Tabs and splitsAny terminal layout, with any agent or command in each pane. Layouts persist across restarts.
  3. Right panelScratchpad pages, local files, and a browser beside the terminal: plans, mockups, handoffs, previews.
  4. Status and chipsLive agent status and notifications, plus links like PR #128 or ENG-412 pinned to a workspace.
  5. The toastty CLIEvery piece above, callable from a skill or a script. Skills in ~/.toastty/skills reach every supported agent you launch.
Workflows

Put the pieces together however you work.

A workflow is a short skill file that tells your agent which pieces to use and when. Start from the worktree examples, or describe how you work and let your agent write one.

Worktree handoff

"hand this off"Example included

Packages the conversation into a handoff, opens a worktree in a new subspace, and comes back with a screenshot report and a PR chip.

git · GitHub

Issue to PR

"start ENG-412"

Reads the issue, names a workspace after it with a chip linking back, drafts the plan in a Scratchpad, and links the PR on the issue when it's up.

Linear · GitHub Issues

Review queue

"review my PRs"

Opens a subspace per requested review with the diff in the browser, writes notes into a Scratchpad, and notifies you as each one is ready.

GitHub

Spec to tasks

"build from this spec"

Opens the spec beside the terminal, splits it into tasks, starts a subspace for each, and keeps a progress page up to date.

Google Docs · Notion · Markdown

Crash to fix

"fix this crash"

Reproduces the report in a worktree with the dev server in a split the agent can read, then shows before and after screenshots.

Sentry · logs

Second opinion

"ask another model"

Runs two agents side by side on the same question and compares their answers in a Scratchpad.

Any two CLI agents

The worktree handoff ships as example skills; the others are ideas to describe to your agent. Issue trackers and documents are reached through your agent's own tools, such as MCP servers or gh. Toastty provides the workspace around them.

Sidebar

See which agent needs you next.

Every workspace is a card in the sidebar. Sessions report live status, and the rows that want you are tinted: green when ready, amber when waiting for approval, red on an error.

  • SubspacesTask workspaces nest under the session that started them, each with its own status and PR chip.
  • Jump to what's next⌘⇧A cycles through unread, approval, and active sessions.
  • Mark for later⌘⇧L flags a session; the flag clears when it moves forward.
  • Watch any command⌘⇧M turns a long build or test run into a row that notifies you when it exits.
  • NotificationsNative macOS notifications and unread badges, so you can look away.

Live status for Claude Code, Codex, Cursor, Grok Build, OpenCode, MiMo Code, and Pi. Any other CLI runs in a normal pane.

Toastty Mobile TestFlight beta

Check on your agents from your phone.

The same sidebar, on your iPhone. See which sessions need you, answer the questions your agents ask, and send the next message, all over your private tailnet.

  • Every session, liveWorkspaces and subspaces with live status. Rows that need you are tinted green, amber, or red, just like on the Mac.
  • Answer your agents' questionsWhen an agent asks you to choose, pick an option or type a custom answer. It lands in the terminal on your Mac as if you were there.
  • Reply from anywhereSend the next prompt with photos and files attached, then watch the tool calls come in.
  • Scratchpads and filesOpen the pages, documents, and previews your agents published, and tap a PR chip to read the pull request.
  • Private by designToastty listens only on your Mac, and Tailscale Serve carries the connection over your own tailnet. No Toastty account, no hosted relay.

Available through TestFlight for now. Remote Access covers pairing and the tailnet setup.

Get started

Set up in a few minutes.

Download Toastty

Open the latest release and drag Toastty to Applications. Your Ghostty config carries over.

Paste the setup prompt

Copy it from Toastty ▸ Get Started with Toastty… and give it to any agent in a Toastty pane. It previews every change before writing anything.

Pick a workflow

Copy the worktree handoff examples into ~/.toastty/skills, or describe how you work and let your agent write a skill there.

Foundations

A real terminal underneath.

Ghostty renderingGPU-accelerated, and your existing Ghostty config just works.
Keyboard first⌘⇧P command palette, ⌘D to split, ⌥1–9 to switch workspaces.
Terminal profilesOne-key launchers for tmux, zmx, SSH, or any startup command.
Layouts that persistWorkspaces, tabs, and splits come back after a restart, and with shell integration, so does each pane's history.
Local firstNo usage analytics or telemetry. Beyond update checks, Toastty only connects out for features you use, such as Remote Access or a diagnostics report you choose to send.
Toastty Mobile TestFlight betaCheck on sessions and reply from your iPhone over your private tailnet. See it in action, or read Remote Access to set it up.
