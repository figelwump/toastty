Changes this round

  1. Workspace takes the top-right slot. Where the agent name sat. It reads at body size in secondaryText, truncating at 46% of the card so a long workspace name can't crowd the badge.
  2. Agent drops to the meta line. claude · ~/repos/toastty · 2m ago — still present, still colorless, just no longer competing with status for the eye.
  3. Sort toggle. Two segments under the connection line. Activity is the default; the choice persists in @AppStorage.
  4. No title, message as body. Mirrors SidebarView: status leads, the latest message or approval request is the body clamped to two lines, then the metadata.
  5. Working keeps its word, and approval has no special quote treatment — the request is simply the body.

How the two views differ

  • Activity flattens every workspace into one ranked list, and each card names its workspace top-right. Solves the "urgent item scrolled out of sight" problem without a pinned section.
  • Workspaces keeps group headers, empties the top-right slot, and sorts groups by their most urgent member.
  • One card component serves both, with a showsWorkspace flag and a compact idle variant.
  • Sections stay deleted. The activity sort is the triage surface now, so nothing renders twice in either mode.
Two calls I made inside your ordering: working sits between approval and idle — it is informational, not actionable, but it is live, so burying it under idle felt wrong. And within every bucket, most recent first. Say if you'd rather working sort last.
Where the desktop model needs checking: the sidebar's body text is status.detail — the live message stream. The mobile snapshot currently only carries lastActivity, which for non-idle sessions is the input reason ("Ready for your reply"), not the message. Making the card read like the sidebar means sending a real message excerpt over the wire, so this one is a protocol change, not just a view change.
